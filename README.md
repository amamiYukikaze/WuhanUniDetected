# 武大成分检测器

Wuhan University Detected

一个基于公开网络信息检索，与 LLM 辅助判断，的，中文新闻人物关联检测器。

Chrome（Manifest V3）扩展插件。

## 🧐 这是什么？

使用例

面向中文新闻阅读场景的浏览器扩展工具。

在你**主动点一下悬浮球**之后，检查新闻稿署名人员（或你划出来的人名）的公开履历里是否存在支持其武汉大学教育或任职经历的公开证据。

本质上，是一个【人物实体识别 + 网络搜索 + LLM 证据判读】工具。

「成分」是作者个人的戏谑玩笑说法。扩展**不会**因为某人写过武大新闻，就把他标成武大关系。没有搜索片段里的原句引用，不会标成「检测到武汉大学成分」。

本项目不是身份鉴定器，也不是事实核查工具。本质上是一个借用大量 LLM 和联网搜索实现的新闻页面匹配工具。

## ⚠️ 使用警告 + 免责声明 ⚠️

```
⚠️
请注意，这个插件仅供娱乐。
千万不要将这个插件提供的结果用作任何严肃的判断。
任何时候，我们都建议所有用户再次执行一次人工复核。
```

本项目不是身份认证系统，也不是事实核查系统。

自动化判断可能受到同名人物、姓名简写或别名、网络公开信息不足、搜索引擎结果变化、新闻来源本身存在错误、LLM 判断错误、搜索结果之间的实体关联不明确的等等因素的影响。

因此，“查询到成分”的字样，只表示当前系统找到并判断存在相关公开证据。

**查询到成分并不表示对人物身份的绝对认定。**

始终建议用户根据浏览器插件侧栏提供的原始来源与引用信息进行人工复核。

更多信息请参阅 `DISCLAIMER.md`。

## ✨ 功能

📰 可自动分析新闻页面中的作者及关联创作者

🔍 也支持手动选中文本进行人物检索

🌐 使用第三方互联网搜索服务

🤖 使用 LLM 对搜索结果进行二次证据判断

🔴 三值结果：明确关联、可能关联、未发现关联

📎 提供原始搜索结果及引用信息，方便人工复核

🧩 支持浏览器侧栏查看检测结果

## 🧠 插件行为：它做什么 / 不做什么

默认**进页面什么都不做**：不画框、不跑分词、不调用任何 API。


| 你怎么触发                    | 然后发生什么                                                                    |
| ------------------------ | ------------------------------------------------------------------------- |
| A. 新闻页右侧深红悬浮球            | 把去掉脚本 / 导航 / 评论区后的正文发给 DeepSeek（或你选择使用的LLM APIkey），筛出本稿署名人员，再对每个人做搜索 + 判定 |
| 或者B. 划词后的小红点、右键菜单、或者侧栏输入 | 直接核查这一个名字                                                                 |


一般而言，在进入中文新闻页面后，会自动在右侧出现一个小的悬浮球。

搜索会在点击悬浮球后触发：

```text
⭐点击悬浮球触发 

→ HTML 清理 

→ LLM 提取作者与关联创作者 

→ 人物姓名构建搜索查询 

→ 搜索 API 

→ 搜索结果提交 LLM 证据复核 

→ 三值判断

→ 在页面内人名旁、与侧栏中展示。
```

中文新闻站的 DOM 太乱，本地启发式极易误伤地名和评论区，没有可靠的轻量自动化解法。因此本扩展不在本地硬判人名，而是把去掉脚本、导航、评论区后的正文发给 LLM，让它返回稿件署名人员。

得到名字后，联立关键词“武汉大学” “xx报 编辑/记者/作者…”等，发送给您设置选择的搜索工具API。等待API返回搜索结果后，再交给 LLM 进行一次判读。

也可手动触发搜索：

```text
⭐按下并划动鼠标，选中一个名字文本，随后点击左上角出现的红色小按钮

→ 联立姓名构建搜索查询

→ 搜索 API

→ 结果提交 LLM 证据复核

→ 三值判断

→ 在页面内与侧栏展示。
```

当前暂未支持本地部署的 LLM，但您可协助开发~

## 🔬 怎样才是“关联”？

项目不会仅因为某人：

- 报道过武汉大学
- 写过武汉大学相关新闻
- 在文章中提到武汉大学
- 与武汉大学相关人物有过采访
- 出现在武汉大学相关搜索结果中

就直接判定其存在关联。

当前判断逻辑主要寻找能够直接支持人物与武汉大学之间教育或任职关系的公开信息，  
例如：

- 毕业于武汉大学
- 就读于武汉大学
- 武汉大学在读
- 任教于武汉大学
- 曾任职于武汉大学

具体判断由项目 Prompt 和模型完成。

## 🖥️ 安装

对于 Chrome / Chromium 内核的浏览器：

1. 在本页面右侧，上方，找到 Release，下载最新版本的压缩包。
2. 解压缩这个压缩包，到一个您觉得舒服的位置。
3. 在您的浏览器的地址栏，输入 `chrome://extensions`；或者如果您使用 Edge 浏览器，输入 `edge://extensions`；
4. 在页面左下方，打开【开发者模式 / 开发人员模式】的开关。
5. 回到页面上方，在【开发人员选项】处，找到【加载解压缩的扩展】。
6. 打开本项目的解压文件夹。确保您所选择的文件夹层级，能在打开后看到一个叫 `manifest.json` 的文件即可。

随后，完成配置，即可开始使用。

## ⚙️ 配置与使用

1. 打开扩展设置，填写 **DeepSeek API Key 或者你使用的LLM API Key**。注册之类的，这里就不说啦。
2. 然后，填写博查 / Serper / Tavily 之一的搜索 Key。Key 只存在这台浏览器的 `chrome.storage.local`。同样，注册账号这些就不说啦。
3. 打开侧栏（工具栏弹窗里的「打开侧栏」）。
4. 打开一篇中文新闻，点右侧深红悬浮球。侧栏会显示「筛署名 → 逐人核查」的进度。由于需要多次调用LLM判读，速度会比较慢，这是预期行为，请不要焦急。
5. 也可以：在任意页面，选中名字、划词 / 右键 / 在侧栏输入人名。

页内标签会显示三种结论：确认、疑似、未查询到。右侧边栏会显示相关来源与判读结果。

## 🔐 有关隐私

本项目不会因为安装扩展而自动上传所有浏览历史。

但在执行检测功能时，项目可能需要将以下内容发送给用户配置的第三方服务：

- 当前页面经过处理的文本
- 用户主动选择的文本
- 搜索查询
- 搜索结果
- LLM 分析所需的上下文

具体数据流取决于用户所配置的 LLM 与 Search API。

使用第三方 API 前，请阅读相应服务的隐私政策和服务条款。
